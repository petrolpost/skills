# Observed Pattern: 研发阶段模型

> ⚠️ **这是观察到的经验模式（Observed Pattern），不是理论。**
> 来自研发实践总结，尚未经过足够验证。可能存在 Merge、Fork、Dormant 等未覆盖的状态。
> 如发现不适用，以实际项目信号为准，不要强行套用。

## 阶段判断问题

请用户回答以下问题以确定当前阶段：

1. 最近是否有新概念/新项目不断涌现？ [是 → 偏向探索期 / 否 → 可能已进入收敛期]
2. 团队/自己最近说得最多的关键词是什么？ ["扩展"/"新增" → 探索期 / "收口"/"封顶" → 收敛期]
3. 是否有明确的最近一次发布版本？ [有 → 可能进入观察期 / 无 → 仍在探索或收敛中]
4. 是否遇到了无法调和的内部矛盾？ [是 → 冲突期 / 否 → 看其他信号]

## 六阶段特征参考

| 阶段             | 特征          | 核心任务                    | 常见陷阱        |
| -------------- | ----------- | ----------------------- | ----------- |
| Discovery 发现   | 提出新解释解决当下问题 | 明确定义问题域                 | 跳过问题直接想方案   |
| Expansion 扩展   | 项目/概念不断涌现   | 探索边界，尝试多种模型             | 过度扩展失去焦点    |
| Conflict 冲突    | 内部矛盾不可调和    | 识别真正的冲突点                | 回避冲突，强行统一   |
| Compression 收敛 | 强调收口、封顶、简单  | 去冗余，提取核心                | 过早收敛，扼杀创新   |
| Release 发布     | 形成稳定版本      | 写 Release Notes，记录验证了什么 | 追求完美而推迟发布   |
| Observation 观察 | 收集运行证据      | 等待反馈，准备下一轮              | 忘记观察直接进入下一轮 |
