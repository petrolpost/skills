## Permission Model

**User tier** commands are designed to be safe for anyone operating the agent:
- No persistent state mutation (or mutation is clearly reversible)
- No exposure of system internals
- Documented, predictable output

**Admin tier** commands are for operators and developers only:
- May expose internal state or configuration
- May mutate persistent configuration
- Invoked via `/admin:` namespace prefix
- Not listed in default `/help` output

**Enforcement**: This system does not enforce permissions at a technical level (no auth token
required). Enforcement is by convention: admin commands are in a separate namespace and excluded
from user-facing documentation. Implementations may add authentication if needed.

## Implementation Notes

These are non-binding suggestions for the developer implementing this command system.

**Dispatch pattern**: A simple prefix-match router works for flat commands. For namespaced
commands, split on `:` first, then match within the namespace handler.

**Argument parsing**: Parse `$ARGUMENTS` as a space-separated string. Flags (`--flag`) are
boolean; `key=value` pairs are structured; everything else is positional.

**`/help` implementation**: The self-describing pattern (read registry at runtime) is strongly
recommended over hardcoded lists. This keeps `/help` accurate as the system evolves.

**Error handling contract**: Every command must always respond — never silently fail. At minimum,
output the error and suggest next steps.

**Logging**: Admin commands should log invocation (who, when, what args) if the platform supports it.
